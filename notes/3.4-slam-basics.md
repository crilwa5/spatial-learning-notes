# 3.4 视觉 SLAM 基础与简单实现

## 1. VO：视觉里程计

VO（Visual Odometry）是利用连续图像之间的变化，估计相机自身运动的方法。

简单理解：

> 相机不断拍照，通过比较前后两张图片中相同特征的位置变化，推测相机自己移动了多少。

例如：

```text
第 1 帧 → 第 2 帧 → 第 3 帧 → 第 4 帧
   ↓        ↓        ↓        ↓
 相机移动  相机移动  相机移动  相机移动
```

每次估计的是相邻两帧之间的**相对运动**，然后把这些运动累积起来，就可以得到一条相机轨迹。

### VO 和普通里程计的区别

普通汽车里程计：

```text
车轮转了多少
      ↓
汽车大概走了多少
```

VO：

```text
图像中的物体/特征发生了什么变化
      ↓
相机大概移动了多少
```

因此 VO 可以理解成：

> 用摄像头代替车轮来“估计自己走了多远”。

---

## 2. VO 中的漂移

VO 最大的问题之一是**累计漂移（Drift）**。

假设真实运动是：

```text
1m + 1m + 1m + 1m + ...
```

但每次 VO 都有一点误差：

```text
1.1m
0.9m
1.2m
0.8m
...
```

单独看每一步，误差可能并不大。

但是：

```text
小误差
  ↓
不断累积
  ↓
越来越大的位置偏差
  ↓
最终轨迹和真实轨迹不一致
```

所以 VO 很像一个**视觉计步器**：

> 每一步都在估计，但走得越久，累计误差可能越大。

---

# 3. VIO：视觉惯性里程计

VIO（Visual-Inertial Odometry）是在 VO 的基础上加入 IMU。

```text
VO  = 相机
VIO = 相机 + IMU
```

相机和 IMU 的作用不同。

### 相机

相机负责：

> “我看到了什么？”

例如：

```text
🌳   🏠   🚗
```

它通过观察这些物体在连续图像中的位置变化，推测相机怎么运动。

### IMU

IMU 不看外面的物体，它负责感受：

> “我自己刚才怎么运动？”

例如：

```text
加速
旋转
快速运动
```

可以简单理解成：

> IMU 是相机的“运动感觉器官”。

### 为什么要融合？

相机：

* 可以观察外部世界；
* 可以提供长期的几何信息；
* 但快速运动时可能出现运动模糊。

IMU：

* 对快速运动响应快；
* 不依赖图像；
* 但长期积分容易产生漂移。

因此：

```text
       相机
        ↓
   看外部世界
        ↘
         融合
        ↗
   感受自身运动
        ↑
       IMU
        ↓
       VIO
```

核心思想：

> 相机负责“看”，IMU 负责“感受运动”，两者结合估计相机运动。

---

# 4. 前端跟踪

前端可以理解成 SLAM 系统里的：

> “侦察兵”。

相机每来一张新图片，前端首先要快速处理。

主要工作：

1. 找特征；
2. 找前后帧中相同的特征；
3. 根据这些特征估计相机当前运动；
4. 判断当前帧是否需要成为关键帧；
5. 把结果交给后端。

例如：

第一帧：

```text
🌳       🪑       🚪
 ●        ●        ●
```

第二帧：

```text
   🌳       🪑       🚪
   ●        ●        ●
```

前端会寻找：

```text
第一帧的 ●
     ↓
第二帧中的哪个 ●？
```

如果大量特征都能对应起来，就可以根据这些点的变化估计相机运动。

### 前端的特点

前端主要追求：

> **快**

所以前端得到的结果通常是一个**初步估计**，不一定是最终最准确的结果。

可以记：

```text
前端：
“我觉得相机现在在这里。”

后端：
“我把前面很多帧一起检查一下，再修正。”
```

---

# 5. 后端优化

后端主要负责：

> 把前面很多时刻的数据放在一起，检查它们是否互相一致，并进行修正。

例如前端连续估计：

```text
第1帧 → 第2帧 → 第3帧 → 第4帧
 ↓       ↓       ↓       ↓
位置1    位置2    位置3    位置4
```

每一步都有误差。

后端不会只看某一帧，而是把：

* 相机位姿；
* 三维点；
* 不同帧之间的约束；
* 回环约束；
* IMU 约束；

放在一起进行优化。

可以简单理解成：

> 前端负责“先猜”，后端负责“把之前的猜测一起检查和修正”。

常见后端优化：

* 局部 BA；
* 全局 BA；
* 位姿图优化；
* 因子图优化。

---

# 6. 关键帧

关键帧（Keyframe）就是：

> 比较重要的一张图片，系统把它保存下来，作为后续建图和优化的参考。

不是每一张图片都必须成为关键帧。

例如：

```text
第1帧 ⭐
第2帧
第3帧
第4帧 ⭐
第5帧
第6帧
第7帧 ⭐
```

这样可以减少计算量，同时保留比较重要的场景信息。

# 7. 稀疏地图和稠密地图

## 7.1 稀疏地图

稀疏地图只保存少量重要的三维点。

例如：

```text
        ●

   ●          ●

        ●

              ●
```

这些点通常来自比较稳定的特征点。

作用主要是：

* 相机定位；
* 估计相机轨迹；
* 提供几何约束。

它并不能完整表示物体表面。

---

## 7.2 稠密地图

稠密地图会保存更多场景表面信息。

例如：

* 点云；
* TSDF；
* 网格；
* 3D Gaussian 等。

可以理解成：

```text
稀疏地图：

●      ●
   ●
       ●


稠密地图：

●●●●●●●
●●●●●●●
●●●●●●●
●●●●●●●
```

稠密地图包含的信息更多，因此更适合后面的：

* 物体识别；
* 场景理解；
* 空间关系分析；
* 3D 空间问答。

对于我的研究方向：

> 稀疏地图更偏向“知道相机在哪里”；稠密地图更有利于“理解场景里面有什么、东西在哪里、它们之间是什么关系”。

# 8. 两帧之间的相对位姿

在简单 VO 实现中，经常使用：

```python
R, t = cv2.recoverPose(...)
```

得到两帧之间的相对运动。

其中：

```text
R：旋转
t：平移方向
```

R 是一个：

```text
(3, 3)
```

矩阵。

t 通常是：

```text
(3, 1)
```

向量。

---

## 8.1 为什么 t 不能直接表示真实移动距离？

`recoverPose()` 得到的平移 `t` 只有**方向信息**，尺度是不确定的。

例如：

```text
t = [0.1, 0, 0]
```

不能直接理解成：

> “相机向右移动了 0.1 米。”

它只能大致理解为：

> “相机向这个方向发生了平移。”

原因是单目相机只通过两张普通图片，很难知道真实世界到底有多大。

例如下面两种场景：

```text
小场景：

相机 → 🚗
距离 1m


大场景：

相机 →        🚗
距离 10m
```

如果图像中的几何关系可以对应起来，仅靠单目两帧可能无法确定真实尺度。

因此单目 VO 通常存在：

> **尺度不确定性（Scale Ambiguity）**

如果需要真实米制尺度，通常需要：

* 双目相机；
* RGB-D；
* IMU；
* GPS；
* 已知尺寸物体；
* 其他尺度信息。

# 9. 两帧三角化：从二维点得到三维点

这是从 VO 进一步得到简单三维地图的重要步骤。

核心思想：

```text
第一张图片中的一个点
        ↓
第二张图片中的同一个点
        ↓
结合两个相机的位置和方向
        ↓
得到三维空间中的一个点
```

可以把它理解成：

> 两台相机同时观察同一个东西，通过两条观察方向推测这个东西在空间中的位置。

例如：

```text
相机1 📷 ----------------
          \ 
           \
            ● 三维点
           /
          /
相机2 📷 ----------------
```

第一台相机看到：

```text
像素点 (u1, v1)
```

第二台相机看到：

```text
像素点 (u2, v2)
```

结合：

```text
第一台相机的位置
第二台相机的位置
第一台相机的观测
第二台相机的观测
```

就可以估计：

```text
X, Y, Z
```

于是：

```text
一个匹配点 → 一个三维点

很多匹配点 → 三维点云
```

```python
points1_tri.shape
```

```text
(N, 3)
```

# 11. 投影矩阵 P

在代码中：

```python
P2 = K @ [R | t]
```

其中：

```text
K = 相机内参
R = 相机旋转
t = 相机平移
```

形状分别是：

```text
K      : (3, 3)
[R | t]: (3, 4)

P2     : (3, 4)
```

因此：

```text
P2
(3,4)
```

可以把三维点投影到二维图片上。

# 12. 齐次坐标

普通三维点：

```text
(X, Y, Z)
```

变成齐次坐标：

```text
(X, Y, Z, 1)
```

所以：

```python
points3d_h
```

形状：

```text
(N, 4)
```

例如：

```text
(X1,Y1,Z1,1)
(X2,Y2,Z2,1)
...
```

然后：

```python
P2 @ points3d_h.T
```

得到：

```text
(N, 3)
```

再通过除以最后一个坐标，把齐次坐标转换成普通像素坐标：

```text
(x, y, w)
 ↓
(x/w, y/w)
```

最终得到：

```text
(N, 2)
```

即图片上的像素坐标。

# 13. 重投影误差

重投影误差是这一节非常重要的概念。

过程：

```text
三维点
  ↓
使用相机位姿
  ↓
重新投影到第二张图片
  ↓
得到预测像素位置
  ↓
和真实像素位置比较
  ↓
得到误差
```

例如真实位置：

```text
真实点：
(500, 300)
```

重新投影得到：

```text
预测点：
(503, 304)
```

那么两者之间存在像素误差。

可以理解为：

> “我根据三维点和相机位置猜出来的像素位置，和真正看到它的位置差了多少。”

误差越小，说明：

```text
三维点
 +
相机位姿
```

之间越一致。

---

# 14. 重投影误差的 Shape

假设有 N 个点：

```python
points2_valid
```

形状：

```text
(N, 2)
```

表示真实像素：

```text
[u1,v1]
[u2,v2]
...
```

预测像素：

```python
projected_pixels
```

也是：

```text
(N, 2)
```

因此：

```python
projected_pixels - points2_valid
```

仍然是：

```text
(N, 2)
```

然后：

```python
np.linalg.norm(..., axis=1)
```

会对每个点的 `(dx, dy)` 求长度。

最终：

```text
(N,)
```

也就是：

```text
每个三维点对应一个重投影误差
```

# 15. solvePnP

solvePnP 解决的问题可以简单理解成：

> 已经知道三维点，也知道这些点在图片中的位置，现在反过来调整相机的位置和方向。

输入：

```text
三维点
    ↓
(X,Y,Z)

图片中的二维点
    ↓
(u,v)

相机内参
    ↓
K
```

输出：

```text
R
t
```

也就是相机位姿。

所以：

```text
已知 3D + 已知 2D
        ↓
    solvePnP
        ↓
    相机 R、t
```

在我们的代码中，它的作用是：

> 用已经三角化得到的三维点和第二帧真实观察到的二维点，进一步调整第二台相机的位姿，让重投影误差尽可能小。

# 16. Rodrigues：旋转矩阵和旋转向量互相转换

OpenCV 的 solvePnP 使用：

```text
rvec
```

表示旋转。

而前面使用的是：

```text
R
```

旋转矩阵。

因此需要：

```python
rvec, _ = cv2.Rodrigues(R)
```

把：

```text
R
(3,3)
```

转换成：

```text
rvec
(3,1)
```

优化之后再：

```python
R, _ = cv2.Rodrigues(rvec)
```

把它变回：

```text
R
(3,3)
```

所以：

```text
旋转矩阵 R
    ↓ Rodrigues
旋转向量 rvec
    ↓ solvePnP
优化后的 rvec
    ↓ Rodrigues
旋转矩阵 R
```

# 17. 简化版 BA

BA 是 Bundle Adjustment，中文通常叫：

> 光束法平差 / 束调整。

完整 BA 会同时优化：

```text
相机位姿
+
三维地图点
```

我们的代码为了方便理解，没有直接实现完整 BA，而是使用了一个非常简单的**交替优化**。

核心思想：

```text
固定三维点
    ↓
优化相机位姿
    ↓
固定相机位姿
    ↓
重新计算三维点
    ↓
重复
```

也就是：

```text
第 1 轮
3D点 ──→ solvePnP ──→ 相机位姿
 ↑                       ↓
 └────── 三角化 ←────────┘

第 2 轮
继续重复
```

代码：

```python
for iteration in range(5):
```

表示重复 5 次。

---

# 18. BA 每一轮具体发生什么？

## 第一步：计算当前误差

先用当前：

```text
三维点
+
相机位姿
```

重新投影。

然后计算：

```text
平均重投影误差
```

记录：

```python
error_history.append(mean_error)
```

这样可以观察优化有没有变好。

---

## 第二步：固定三维点，优化相机

调用：

```python
cv2.solvePnP(...)
```

相当于告诉程序：

> “这些三维点先不要动，你调整一下相机位置和方向，让它们投影到图片上的位置更加准确。”

得到：

```text
R_current
t_current
```

---

## 第三步：固定相机，重新三角化

现在相机位姿已经更新。

于是重新使用：

```text
第一帧二维点
第二帧二维点
新的相机位姿
```

进行三角化。

得到新的：

```text
points3d_current
```

相当于：

> “相机位置变了，那么这些三维点的位置也重新算一次。”

---

## 第四步：检查点是否有效

代码：

```python
(points_in_camera1[:,2] > 0)
&
(points_in_camera2[:,2] > 0)
```

检查三维点的 Z 是否大于 0。

因为正常情况下：

```text
相机前方：

        ●
       /
      /
     📷
```

三维点应该位于相机前面。

如果点跑到了相机后面：

```text
● -------- 📷
```

那么这个点通常是不合理的。

所以把这些点过滤掉。

---

# 19. 简化 BA 的整体流程

可以把整个过程记成：

```text
初始三维点
    +
初始相机位姿
    ↓
计算重投影误差
    ↓
固定三维点
    ↓
solvePnP 优化相机
    ↓
得到新的相机位姿
    ↓
固定相机位姿
    ↓
重新三角化
    ↓
得到新的三维点
    ↓
过滤无效点
    ↓
重新计算误差
    ↓
重复几轮
```

目标就是：

```text
重投影误差
      ↓
尽可能变小
```

# 20. Shape 速查

这一节最重要的 Shape 可以记成：

| 数据        | Shape     | 含义              |
| --------- | --------- | --------------- |
| 单张 RGB 图像 | `(H,W,3)` | 高、宽、RGB         |
| 灰度图       | `(H,W)`   | 每个像素一个灰度值       |
| 匹配二维点     | `(N,2)`   | N 个 `(u,v)`     |
| 三维点       | `(N,3)`   | N 个 `(X,Y,Z)`   |
| 齐次三维点     | `(N,4)`   | N 个 `(X,Y,Z,1)` |
| K         | `(3,3)`   | 相机内参            |
| R         | `(3,3)`   | 旋转矩阵            |
| t         | `(3,1)`   | 平移向量            |
| `[R\|t]`  | `(3,4)`   | 外参              |
| P         | `(3,4)`   | 投影矩阵            |
| 投影后的齐次点   | `(N,3)`   | `(x,y,w)`       |
| 投影后的像素    | `(N,2)`   | `(u,v)`         |
| 每个点的重投影误差 | `(N,)`    | 每个点一个误差         |
| 轨迹        | `(T,3)`   | T 个相机中心         |

这一节并不是实现一个完整的工业级 SLAM。

而是从最简单的两帧开始，把 SLAM 中几个核心概念串起来：

```text
两张图片
   ↓

   ↓

   ↓

   ↓
recoverPose
   ↓
得到相对 R、t
   ↓
累积相对位姿
   ↓
得到相机轨迹
   ↓
两帧三角化
   ↓
得到三维点
   ↓
重新投影
   ↓
计算重投影误差
   ↓
solvePnP
   ↓
优化相机位姿
   ↓
交替优化三维点和相机
   ↓
简化 BA
```

因此这份代码实际上是在用一个非常小的例子理解：

```text
VO

↓
三角化
↓
三维地图
↓
重投影误差
↓
位姿优化

简化 BA
```

# 22. 和真正 SLAM 的关系

目前代码还比较简单。

真正的 SLAM 通常还会加入：

```text
连续视频
   ↓
前端跟踪
   ↓
关键帧
   ↓
局部地图
   ↓
后端优化
   ↓
```

# 24. 本节最核心的几句话

### VO

> 通过连续图像的变化，估计相机怎么移动。

### VIO

> 相机负责看，IMU 负责感受自身运动，两者结合估计相机运动。

### 前端

> 快速寻找前后帧对应关系，并估计当前相机的大概位置。

### 后端

> 把多个时刻的数据放在一起检查和优化，让它们尽可能一致。

### 三角化

> 同一个点被两个不同位置的相机看到，通过两个观察结果估计它的三维位置。

### 重投影

> 把三维点重新投回图片，看预测位置和真实位置差多少。

### solvePnP

> 已知三维点和图片中的二维点，反过来调整相机位姿。

### BA

> 相机位姿和三维点互相调整，让整体重投影误差变小。

### 稀疏地图

> 少量重要三维点，主要用于定位和几何估计。

### 稠密地图

> 更完整的三维场景表示，更适合后续场景理解。

# 28. VO 相对位姿实验

## 28.1 相邻帧的问题

一开始处理：

```text
0.jpg -> 1.jpg
```

得到：

```text
pose_inliers = 0
```

原因：

- 相邻帧位移太小；
- 视差不足；
- 本质矩阵几何条件不稳定；
- 不是代码报错，而是输入基线不合适。

重要经验：

> 对 VO 来说，相邻帧不是越近越好，需要足够的相机位移和视差。

## DSO 直接法最小实验

直接法不主要依赖特征描述子，而是比较投影前后的像素亮度。

实验流程：

像素
-> 相机坐标射线
-> 假设深度
-> 得到三维点
-> 假设 R、t
-> 投影到第二帧
-> 计算光度误差

实际结果：

第一帧像素 (480, 640)，亮度 196
第二帧同一位置亮度 167，误差 29
第二帧预测位置 (454, 640)，亮度 184，误差 12

结论：

预测位置比同一位置更接近第一帧亮度，说明直接法通过相机运动、深度和投影，让投影前后的亮度差变小。

当前实验只用了单像素、近似内参和人为假设的深度与 R、t，不是完整 DSO。
